### Configs — `src/configs/`

#### `DatagenConfig` (`datagen.py`)
Parâmetros exclusivos do motor e da simulação. Importado por `generate_data.py`,
`build_data_chunks.py`, `motor_model.py`, `data_utils.py` e scripts auxiliares.

| Campo | Padrão | Descrição |
|---|---|---|
| `dataset` | `'motor_uniform'` | nome do dataset — define subdiretórios em data/ |
| `n_r`, `n_a` | `80`, `240` | células radiais e angulares |
| `ang_1`, `ang_2` | `0`, `120` | ângulo inicial e final (graus) |
| `mode` | `'qtree'` | `'grid'` ou `'qtree'` |
| `distribution` | `'uniform'` | distribuição de amostras |
| `n_samples`, `n_phases`, `max_depth` | `4000`, `2`, `1` | parâmetros de geração |
| `datagen_seed` | `12` | semente para `BLDC_Process.generate_samples` |
| `refinement_ref_factor` | `1.2` | fator do disco grande em `_make_compute_fn` (legado; substituído por retângulo polar na próxima sessão) |
| `cascade_buffer` | `None` | camadas adjacentes arrastadas ao refinamento |
| `homogeneity_threshold` | `0.90` | frac_dom ≥ threshold → célula homogênea, não refina (adicionado na próxima sessão) |
| `chunk_size` | `32` | amostras por arquivo `.pt` |
| `npz_parser` | `'MaskedFNO2d'` | parser para gen_npz_structures — chave em `PARSER_REGISTRY` |
| `npz_samples_per_worker` | `2` | amostras por processo paralelo |
| `npz_max_workers` | `12` | limite de workers (segurança térmica — i9-13900KF) |
| `npz_max_samples` | `None` | limite de amostras a processar; None = todas |

#### `NnCfg` + arch configs (`training.py`)
Treino completamente independente do datagen — `NnCfg.dataset` é a fonte de verdade
para os scripts de treino; `DatagenConfig` não é importado por eles.

**`NnCfg`**

| Campo | Padrão | Descrição |
|---|---|---|
| `dataset` | `'motor_uniform'` | dataset a treinar (independente do DatagenConfig) |
| `arch` | `'FNO_GNN'` | chave de arquitetura em ARCH_REGISTRY |
| `loss` | `'mse'` | função custo |
| `problem` | `'motor'` | identificação do problema (para diretórios de log) |
| `lr` | `1e-3` | learning rate |
| `n_epochs` | `500` | épocas de treino |
| `scheduler` | `'step'` | tipo de scheduler (`'step'` → StepLR) |
| `scheduler_step` | `100` | passo do StepLR |
| `scheduler_gamma` | `0.5` | fator de decaimento do StepLR |
| `batch_size` | `32` | amostras por mini-lote |
| `train_split` | `0.70` | fração de chunks para treino |
| `buffer_size` | `64` | amostras no reservatório de shuffle |
| `num_workers` | `2` | workers de leitura |
| `prefetch_factor` | `2` | batches pré-buscados por worker |
| `split_seed` | `12` | semente para split treino/teste |
| `resume_run` | `None` | caminho para `run_XXXX/` existente a retomar; `None` = treino do zero |
| `resume_checkpoint` | `'latest'` | qual checkpoint carregar: `'latest'` ou `'best'` |
| `resume_modified` | `False` | `False` = carrega model+optimizer+scheduler; `True` = só pesos |
| `arch_cfg` | `None` → auto-instanciado | instância da config de arquitetura; se `None`, `__post_init__` cria `ARCH_REGISTRY[arch].cfg_cls()` automaticamente; se passado explicitamente, tipo é validado contra o arch |
| `monitor_cfg` | `MonitorCfg()` | checkpointing, early stop e logging |

**`MonitorCfg`** (`monitor.py`)

| Campo | Padrão | Descrição |
|---|---|---|
| `checkpoint_every` | `50` | heartbeat — salva checkpoint a cada N épocas |
| `early_stop_patience` | `None` | heartbeats sem melhora antes de parar (`None` = desativado) |
| `early_stop_min_delta` | `1e-6` | melhora mínima em `test_loss` para resetar patience |
| `save_best` | `True` | salva `*_best.pth` sempre que `test_loss` melhora |

`patience` conta em **heartbeats**, não em épocas: `patience=3, checkpoint_every=50` → para após 150 épocas sem melhora.

**Arch configs** — campos batem 1:1 com os `__init__` de cada modelo;
`entry.model_kwargs(arch_cfg)` filtra campos não-construtores (ex: `lambda_loss`).

- **`FNOConfig`**: `in_channels=2`, `out_channels=2`, `modes1/2=240`, `conv_width=8`,
  `conv_layers=4`, `lift_width/proj_width=64`, `lift_layers/proj_layers=3`, `data_res=(80,240)`
- **`FNO_GNNConfig`**: mesmos campos FNO com prefixo `fno_`, mais `data_res=(80,240)`,
  `gnn_node_width=32`, `gnn_n_layers=3`, `lambda_loss=0.5`
- **`MaskedFNO_GNNConfig`**: idêntico a `FNO_GNNConfig`; FNO tem `out_channels=8` hardcoded no modelo;
  `lambda_loss` filtrado de `model_kwargs` (igual ao `FNO_GNNConfig`)
- **`FNORefConfig`**: `in_channels=1`, `out_channels=1`, `n_modes=(12,12)`, `hidden_channels=64`,
  `n_layers=4`, `lifting_channel_ratio=2.0`, `projection_channel_ratio=2.0`, `data_res=(128,128)`;
  `data_res` não é passado ao construtor (`model_kwargs` o filtra); parâmetros mapeiam direto para API `neuralop.models.FNO`
- **`PhiDeepONetConfig`**: [REMOVIDO] — removida do escopo ativo (2026-05-27); código comentado em `configs/training.py`

**Uso típico:**
```python

# arch_cfg explícito — para sobrescrever campos específicos

```

### ARCH_REGISTRY — `src/neural_op/archs/__init__.py`

Registro central de arquiteturas. Cada entrada é um `ArchEntry` (dataclass):

| Campo | Tipo | Descrição |
|---|---|---|
| `cls` | `type` | classe do modelo (FNO2d, FNO_GNN, …) |
| `cfg_cls` | `type` | dataclass de config correspondente |
| `loader_mode` | `str` | `'grid'` ou `'qtree'` — passado direto ao `build_loaders` |
| `model_kwargs` | `callable` | `(arch_cfg) -> dict` com kwargs do construtor (filtra campos extras) |
| `make_step_fn` | `callable` | `(arch_cfg) -> step_fn(batch, model, loss_fn, device)` |
| `eval_fn` | `callable` | `(model, chunk_data, eval_cfg) -> None` — inferência + plot |

`ArchEntry.make_model(arch_cfg)` é atalho para `cls(**model_kwargs(arch_cfg))`.

```python
# Adicionar nova arquitetura:
ARCH_REGISTRY['MinhaArch'] = ArchEntry(
    cls=MinhaArch, cfg_cls=MinhaConfig, loader_mode='grid',
    model_kwargs=lambda cfg: asdict(cfg),
    make_step_fn=lambda cfg: minha_step_fn,
    eval_fn=minha_eval_fn,
)
```

### Formatos de dados
- Grade regular: `[B, C, H=80, W=240]` (80 radial × 240 angular, 0°–120°)

#### Chunks de dados — gerados por `build_data_chunks.py`

**`data/torch/data_chunks/<dataset>/data_chunk_XXXX.pt`**

Conteúdo varia conforme o parser/modo de `gen_npz_structures`. Campos legados de stream
(`x`, `y`, `depth`, `cells`) são sempre descartados por `_DROP_KEYS`. A detecção de modo
é automática pelo primeiro `.npz` (`has_graph = 'edge_index' in files`).

**Modo grid** (`GridSampleUnifier` — FNO2d, MaskedFNO2d):
```
x_hw:  [B, Cx, H, W]  float32  entrada na grade base (point query — fronteiras nítidas)
y_hw:  [B, Cy, H, W]  float32  saída na grade base
dim:   (H, W)
```

**Modo qtree** (`QtreeSampleUnifier` — FNO_GNN):
```
x_hw:       [B, Cx, H, W]  float32  entrada na grade baixa (média ponderada qtree)
y_hw:       [B, Cy, H, W]  float32  saída na grade baixa
x_hw_grid:  [B, Cx, H, W]  float32  entrada na grade base (point query — fronteiras nítidas)
y_hw_grid:  [B, Cy, H, W]  float32  saída na grade base (point query — fronteiras nítidas)
node_x:     [S_tot, N_x]   float32  features de entrada por nó (colunas do parser)
node_y:     [S_tot, N_y]   float32  features de saída por nó   (colunas do parser)
edge_index: [2, E_tot]     int64    arestas bidirecionais; índices globais no chunk
edge_attr:  [E_tot, N_ea]  float32  features de aresta (colunas do parser)
L:          [B]            int64    nós por amostra
E_L:        [B]            int64    arestas (bidirecionais) por amostra
dim:        (H, W)
```

#### CSVs raw — motor quadtree (fonte única; parsers constroem o que precisam)

**Um único arquivo de depth por amostra** — `depth_qt_` — gerado pelo DFS de `save_material_mu_qtree`.
M e B são amostrados a posteriori sobre essa estrutura; não geram depth próprio.

| Campo | Prefixo CSV | Depth compartilhado | Origem | Observação |
|-------|-------------|---------------------|--------|------------|
| mu_r | `Mu_r_qt_` | `depth_qt_` | Shapely | permeabilidade no ponto central (point query) |
| frac_dom | `Frac_dom_qt_` | `depth_qt_` | Shapely | fração do material dominante na bbox cartesiana |
| M | `Mag_M_qt_` | `depth_qt_` | Shapely | M no ponto central, sem average |
| Bx | `Mag_Bx_qt_` | `depth_qt_` | FEMM | campo radial |
| By | `Mag_By_qt_` | `depth_qt_` | FEMM | campo angular |

Campos derivados em tempo de parse (não salvos como CSV): `material_id`, `cell_area`, `r_base`, `c_base`.
`normal_x` / `normal_y` — pós-processamento futuro (gradiente de frac_dom); placeholder zeros por enquanto.

#### Referência de features por nó — motor quadtree
> Tabela de referência: todos os campos disponíveis a partir dos CSVs raw.
> Cada parser de arquitetura seleciona e constrói o subconjunto relevante.

| Índice | Feature | Detalhes |
|--------|---------|---------|
| `[:,0]` | material_id | categórico: ferro=0, ar=1, ima=2, bobina=3 (derivado de mu_r) |
| `[:,1]` | mu_r | permeabilidade do material no ponto central da célula |
| `[:,2]` | M | magnetização no ponto central da célula (sem média) |
| `[:,3]` | cell_area | área da célula em unidades de célula base = (1/2^depth)² |
| `[:,4]` | r_base | coordenada radial normalizada [0,1] do centro da célula base |
| `[:,5]` | c_base | coordenada angular normalizada [0,1] do centro da célula base |
| `[:,6]` | frac_dom | fração de área do material dominante na célula |
| `[:,7]` | normal_x | normal à interface mais próxima, zero em homogêneas *(pós-processamento)* |
| `[:,8]` | normal_y | normal à interface mais próxima, zero em homogêneas *(pós-processamento)* |

**`node_y` (saída por nó):**
| `[:,0]` | Bx | campo radial (T) |
| `[:,1]` | By | campo angular (T) |

#### Referência de features por aresta — motor quadtree

| Índice | Feature | Detalhe | Custo lazy |
|--------|---------|---------|------------|
| `[:,0]` | delta_r | diferença radial j−i em unidades de célula base | inevitável (loop de adjacência) |
| `[:,1]` | delta_c | diferença angular com wrap | inevitável |
| `[:,2]` | shared_length | comprimento da fronteira compartilhada = min(side_i, side_j) | inevitável |
| `[:,3]` | center_dist | distância euclidiana entre centros = √(Δr²+Δc²) | inevitável |
| `[:,4]` | delta_mu | mu_r[j] − mu_r[i] | **lazy** — só computado se 4 ∈ `edge_attr_cols` |

**`x_hw` e `y_hw` — `[B, 2, H, W]`**
| Dimensão | Significado |
|----------|-------------|
| `B` | amostras no chunk |
| canal 0 | Mu_r (em x_hw) / Bx (em y_hw) |
| canal 1 | M (em x_hw) / By (em y_hw) |
| `H=80` | grade radial |
| `W=240` | grade angular |

#### Convenções do grafo
- **Nós**: cada folha do stream quadtree é um nó (S nós por amostra)
- **Arestas**: adjacência física — dois nós conectados sse regiões compartilham fronteira de comprimento positivo (não apenas ponto)
- **Bidirecional**: par (i,j) e (j,i) ambos presentes; delta_r/delta_c/delta_mu invertidos no par reverso; shared_length e center_dist idênticos
- **Wrap angular**: coluna 0 conecta com coluna W−1 (topologia de anel); radial sem wrap
- **Slicing por amostra**: nós via `cumsum(L)`, arestas via `cumsum(E_L)`; índices em `edge_index` globais no chunk

#### Mapeamento de canais quadtree — CSVs de origem
Todos os campos compartilham o mesmo `depth_qt_` (único DFS em `save_material_mu_qtree`).

| Canal | Tensor | Índice | Prefixo CSV | Depth |
|-------|--------|--------|-------------|-------|
| Mu_r  | x_hw   | 0      | `Mu_r_qt_`    | `depth_qt_` |
| M     | x_hw   | 1      | `Mag_M_qt_`   | `depth_qt_` |
| Bx    | y_hw   | 0      | `Mag_Bx_qt_`  | `depth_qt_` |
| By    | y_hw   | 1      | `Mag_By_qt_`  | `depth_qt_` |

### Modelos — `src/neural_op/archs/`

Blocos de baixo nível compartilhados em `_blocks.py`:
- **`NodeMLP`** — MLP sobre features de nó `[N, in_ch] → [N, out_ch]`
- **`MLP`** — MLP sobre grade `[B, C, H, W] → [B, C', H, W]`; usado por FNO para lift/proj
- **`SpectralConv`** — convolução espectral 2D via rfft2/irfft2
- **`FNO_Blocks`** — sequência SpectralConv + bypass linear com ativação
- **`EdgeConvLayer`** — message passing com gate escalar por aresta
- **`GNN`** — N camadas EdgeConvLayer com lift/proj linear

Arquiteturas de alto nível:
- **`FNO2d`** (`archs/fno.py`): Lift(MLP) → FNO_Blocks → Proj(MLP). Entrada `[B,C,H,W]`.
- **`FNO_GNN`** (`archs/fno_gnn.py`): FNO2d na grade → interpolação bilinear nos nós quadtree
  → GNN correção residual (ΔBx, ΔBy). Saídas: `y_hw_fno [B,2,H,W]` + `y_nodes [S_tot,2]`.
- **`FNORef`** (`archs/fno_ref.py`): wrapper fino sobre `neuralop.models.FNO` (biblioteca `neuraloperator`). Registrado condicionalmente via `try/except ImportError`.
- **`MaskedFNO2d`** (`archs/fno_mat.py`): FNO2d com 8 canais de saída (4 materiais × Bx, By).
  `forward → [B,8,H,W]`; `assemble(pred, masks) → [B,2,H,W]`. Máscara de material derivada
  on-the-fly de `x[:,0]` (Mu_r) por `_make_material_masks`. Loss: `'material_masked'` —
  ponderada pela parcela de domínio de cada material, 50/50 Bx/By.
- **`PhiDeepONet`** (`archs/phi_deeponet.py`): [REMOVIDO] do escopo ativo (2026-05-27). Código comentado no arquivo para referência futura.

### Dataloader de treino (streaming)
`build_loaders` aceita `mode='grid'` ou `mode='qtree'`. O modo é determinado pelo
`loader_mode` do `ArchEntry` — `scripts/train.py` não precisa saber qual usar.

#### mode='grid' — `ChunkStreamDataset` + `CUDAPrefetcher`
- **Chunk**: unidade de I/O — 1 arquivo `data_chunk_*.pt` por vez em RAM. Grafos
  (`edge_index`, `node_x`, …) liberados via `del d` imediatamente após `torch.load`.
  Apenas `x_hw` e `y_hw` são mantidos; cada amostra entra no buffer como view.
- **Batch emitido**: tuple `(x, y)` com shape `[B, 2, H, W]` cada.
- **Buffer**: reservatório de `BUFFER_SIZE` amostras em RAM. Shuffle por substituição O(1).
- **CUDAPrefetcher**: agnóstico ao tipo de batch — usa `_to_device` / `_record_stream`
  recursivos (suportam tensor, dict, list, tuple). Transfere batch N+1 para GPU em stream
  CUDA separado enquanto batch N é processado. No-op em CPU.
- **Split**: feito ao nível de chunk antes de qualquer carregamento.
- `training_utils.train_epoch` / `eval_epoch` usam contador de batches em vez de
  `len(loader)` — necessário pois `IterableDataset` não implementa `__len__`.
- **Windows**: `NUM_WORKERS=0` por padrão — com workers > 0 o script precisa de
  guard `if __name__ == '__main__':` (spawn no Windows).

#### mode='qtree' — `ChunkQtreeDataset` + `qtree_collate`
Usado pelo pipeline FNO+GNN (FNO na grade → GNN refina nos nós quadtree).
- Preserva todos os campos do chunk (grade + grafo); grafos **não** são descartados.
- Cada amostra é emitida como dict com `edge_index` de índices **locais** (0..L[i]-1).
  A subtração de offset durante a iteração cria tensor independente; demais campos são views.
- `qtree_collate` remonta o batch: stack para grade, cat para nós/arestas,
  re-offset acumulado de `edge_index` para índices globais no batch.
- **Batch emitido** (dict já no device via CUDAPrefetcher):
  ```
  x_hw        [B, 2, H, W]   grade de entrada  (canal 0=Mu_r, canal 1=M)
  y_hw        [B, 2, H, W]   grade alvo         (canal 0=Bx,   canal 1=By)
  node_x      [S_tot, 5]     features de nó (entrada) — formato legado; atualizar c/ parser
  node_y      [S_tot, 5]     features de nó (alvo)    — formato legado; atualizar c/ parser
  edge_index  [2, E_tot]     arestas com índices globais no batch
  edge_attr   [E_tot, 4]     features de aresta — formato legado; atualizar c/ parser
  L           [B]            nós por amostra
  E_L         [B]            arestas por amostra
  ```

### Dependências principais
`pyfemm`, `shapely`, `torch`, `numpy`, `pandas`, `matplotlib`. Windows-only (pyfemm + pywin32).

## Benchmark comparativo — FNO + GNN vs. baselines

Objetivo: validar o modelo proposto (FNO_GNN) contra baselines da literatura em datasets
com descontinuidades de coeficiente — proxy do problema EM do motor.

### Decisões de arquitetura

**Princípio geral:** máxima reutilização do pipeline existente. `ModelManager`, `fit()`,
`build_loaders`, `train.py` e `ARCH_REGISTRY` não são modificados — apenas recebem
conteúdo novo (entradas de registro, parâmetros diferentes).

**Datasets externos → chunks:**
Datasets externos (HDF5, NPZ) são convertidos para `data_chunk_*.pt` por parsers
dedicados. O formato de saída é `{x_hw: [B, C, H, W], y_hw: [B, C, H, W]}` — idêntico
ao do motor, com `C` variável por dataset (ex: `C=1` para Darcy). A partir dos chunks,
todo o pipeline (`ChunkStreamDataset`, `CUDAPrefetcher`, `build_loaders`) funciona sem
modificação.

**Logs de treino e de eval são completamente independentes:**
- `ModelManager` escreve `config.json` + `metrics.jsonl` + `status.txt` durante treino
- `BenchEvalManager` (novo) escreve apenas `eval_results.jsonl` no mesmo `run_XXXX/`
- Nunca há campos compartilhados ou compatibilidade forçada entre os dois arquivos
- Um run pode ter `eval_results.jsonl` sem `metrics.jsonl` (modelo importado externamente)

**IDs de run sem escopo global:**
`run_0001` é número local a `data/logs/{problem}/{arch}/`. Não há ID global.

**Modelos externos — dois casos:**
1. Treinado por nós via `train.py` com wrapper `ArchEntry` → run normal com `metrics.jsonl`
2. Importado já treinado → `BenchEvalManager` cria `run_XXXX/` leve (só `eval_config.json`
   + `model_final.pth` + `eval_results.jsonl`); sem `metrics.jsonl`, sem `ModelManager`

**Zero-shot:** `bench_eval.py` recebe `--run_dir` + `--eval_dataset` independentemente.
O mesmo run pode acumular múltiplas entradas em `eval_results.jsonl`.
